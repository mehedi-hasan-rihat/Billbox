# Recurring Bills API

Base path: `/api/v1/recurring`

All endpoints require authentication: `Authorization: Bearer <token>`

A recurring rule is a template that automatically generates a new bill at a defined interval. Each generated bill is a normal bill linked back to its rule — it follows the standard bill lifecycle independently.

---

## How It Works

```
Create rule → scheduler runs daily at 01:00
  → finds rules where nextGenerateAt <= now AND status = ACTIVE
    → generates Bill (source = MANUAL, type = RECURRING, status = UNPAID)
    → advances nextGenerateAt to the next cycle
    → records RECURRING_GENERATED event on the bill
```

The bill is created `generateDaysBefore` days before the due date, so it shows as `UPCOMING` immediately.

---

## Frequency & Day Rule

| Frequency | dayRule format | Example | Meaning |
|-----------|---------------|---------|---------|
| `MONTHLY` | `"1"`–`"28"` | `"10"` | Every month on the 10th |
| `WEEKLY` | `"0"`–`"6"` (0=Sun) | `"1"` | Every Monday |
| `YEARLY` | `"MM-DD"` | `"10-01"` | Every Oct 1st |

---

## Recurring Status

| Status | Meaning |
|--------|---------|
| `ACTIVE` | Scheduler generates bills normally |
| `PAUSED` | Scheduler skips this rule — no bills generated |
| `STOPPED` | Permanently stopped — cannot be reactivated |

## Endpoints

### POST /recurring

Create a new recurring rule.

**Request Body**

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| name | string | Yes | Bill title template |
| category | BillCategory | Yes | |
| amount | string (decimal) | Yes | e.g. `"1200.00"` |
| note | string | No | |
| senderBillerId | string | No | Biller from your list |
| frequency | `MONTHLY` \| `WEEKLY` \| `YEARLY` | Yes | |
| dayRule | string | Yes | See frequency table above |
| generateDaysBefore | number | No | Days before due date to generate. Default: `5` |
| startAt | ISO date | No | First generation start. Defaults to now |
| endsAt | ISO date | No | When recurrence ends. Null = forever |

**Example — monthly Internet bill on the 10th, generated 5 days before**

```bash
curl -X POST http://localhost:3000/api/v1/recurring \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Internet Bill",
    "category": "INTERNET",
    "amount": "1200.00",
    "frequency": "MONTHLY",
    "dayRule": "10",
    "generateDaysBefore": 5
  }'
```

**Example Response (201)**

```json
{
  "success": true,
  "data": {
    "id": "clx...",
    "userId": "clx...",
    "name": "Internet Bill",
    "category": "INTERNET",
    "amount": "1200.00",
    "frequency": "MONTHLY",
    "dayRule": "10",
    "generateDaysBefore": 5,
    "status": "ACTIVE",
    "nextGenerateAt": "2026-10-05T00:00:00.000Z",
    "endsAt": null,
    "createdAt": "2026-10-01T08:00:00.000Z"
  },
  "timestamp": "2026-10-01T08:00:00.000Z"
}
```

**Errors**

| Status | Message |
|--------|---------|
| 400 | Validation errors |
| 404 | Biller not found |

### GET /recurring/:id

Get a single recurring rule by ID.

**Errors**

| Status | Message |
|--------|---------|
| 404 | Recurring rule not found |

---

### PATCH /recurring/:id

Update a recurring rule. All fields optional. Changes take effect on the next generation cycle.

**Request Body**

| Field | Type |
|-------|------|
| name | string |
| category | BillCategory |
| amount | string (decimal) |
| note | string |
| senderBillerId | string \| null |
| dayRule | string |
| generateDaysBefore | number |
| endsAt | ISO date \| null |

---

### POST /recurring/:id/pause

Pause an `ACTIVE` rule. The scheduler will skip it until resumed.

**Errors**

| Status | Message |
|--------|---------|
| 400 | Rule is STOPPED, only ACTIVE rules can be paused |
| 404 | Recurring rule not found |

---

### POST /recurring/:id/resume

Resume a `PAUSED` rule. Generation continues from the next scheduled cycle.

**Errors**

| Status | Message |
|--------|---------|
| 400 | Rule is ACTIVE, only PAUSED rules can be resumed |
| 404 | Recurring rule not found |

---

### POST /recurring/:id/stop

Permanently stop a rule. Cannot be undone.

**Errors**

| Status | Message |
|--------|---------|
| 400 | Rule is already stopped |
| 404 | Recurring rule not found |

## Generated Bills

Bills generated by a recurring rule:
- Have `source = MANUAL` and `type = RECURRING`
- Have `recurringRuleId` set — links back to the rule
- Start as `UNPAID` (shown as `UPCOMING` if dueDate is in the future)
- Are fully independent — paying one does not affect others
- Appear in `GET /bills` like any other bill
- Have a `RECURRING_GENERATED` event in their timeline

```bash
# Find all recurring-generated bills
GET /api/v1/bills?type=RECURRING

# View the timeline of a generated bill
GET /api/v1/bills/:id/timeline
```

---

## Idempotency

The scheduler uses `nextGenerateAt` as the generation lock. Even if the job runs twice (e.g. on retry), a bill is only generated once per cycle because `nextGenerateAt` is advanced atomically inside a transaction before the job can pick up the same rule again.
